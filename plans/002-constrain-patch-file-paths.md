## Why This Matters

Patch route IDs are interpolated directly into filesystem paths. The create route uses `randomUUID()`, but the read/update/delete routes trust whatever route parameter arrives. The fix should enforce the same UUID contract at every patch-by-id endpoint and add a path containment guard so future route changes cannot accidentally reintroduce traversal.

## Steps

### Step 1: Create a patch storage helper

Create `app/server/utils/patch-storage.ts`. It should export:

- `PATCH_ID_PATTERN`: a UUID pattern matching IDs generated by `randomUUID()`.
- `assertPatchId(id: string | undefined): string`: throws `createError({ statusCode: 400, statusMessage: 'Invalid patch id' })` if the value is missing or not a UUID.
- `getPatchDirectory(dataStoreDirectory = process.env.DATA_STORE_DIRECTORY): string`: throws a 500 `createError` with a friendly status message if the env var is missing; otherwise returns the patch directory path.
- `getPatchFilePath(id: string, dataStoreDirectory = process.env.DATA_STORE_DIRECTORY): string`: validates the id, resolves the directory and candidate path, and verifies the resolved candidate remains under the resolved patch directory.

Implementation constraints:

- Use `resolve` and `relative` from `node:path` or `path` for the containment check.
- The helper should return paths ending in `${id}.json` only after validation.
- Do not include user-provided path segments in thrown messages.

**Verify**: `cd app && bun run typecheck` -> exit 0. If Plan 001 has not landed and `typecheck` does not exist, STOP and complete Plan 001 first.

### Step 2: Add helper tests

Create `app/server/utils/patch-storage.test.ts` with Vitest tests for:

- A known UUID returns a path below the provided temp base directory.
- `undefined`, `''`, `abc`, and a traversal-shaped value are rejected by `assertPatchId` or `getPatchFilePath`.
- `getPatchFilePath(validUuid, tempBase)` produces a path that ends with `patches/<uuid>.json` using platform-safe path checks.
- Missing data store directory throws a 500-style error.

Use a safe fake base path from `node:os.tmpdir()` or a literal test path. Do not read `.env`.

**Verify**: `cd app && bun run test` -> exit 0 and includes `patch-storage.test.ts`.

### Step 3: Replace direct path construction in by-id routes

Update the three by-id routes:

- In `[id].get.ts`, replace the current missing-id check and `join(...)` call with `const filePath = getPatchFilePath(getRouterParam(event, 'id'))`.
- In `[id].post.ts`, validate once: `const id = assertPatchId(getRouterParam(event, 'id'))`, then `const dir = getPatchDirectory()` and `const filePath = getPatchFilePath(id)`. Preserve the returned patch's `id` field.
- In `[id].delete.ts`, use `getPatchFilePath(getRouterParam(event, 'id'))`.

Import helpers explicitly from `../../utils/patch-storage` or the correct relative path from each route file. Do not rely on auto-imports for server utilities in this plan; explicit imports make tests and drift review clearer.

**Verify**: `cd app && bun run test` -> exit 0.
